# Flujo de trabajo para Cline

1. Leer PRD, diseño y memoria.
2. Identificar el requisito concreto y los supuestos pendientes.
3. Formular una hipotesis tecnica verificable.
4. Localizar el modulo que controla directamente el comportamiento.
5. Proponer los archivos que se modificaran.
6. Implementar el cambio minimo.
7. Ejecutar la validacion mas cercana al cambio.
8. Corregir errores de la misma superficie antes de ampliar el alcance.
9. Actualizar documentacion y memoria si cambia el comportamiento.
10. Informar cambios, validaciones y pendientes.

Cuando el usuario proporcione nuevos requisitos, actualizar primero PRD y
DESIGN.md, registrar decisiones obsoletas y despues modificar el codigo.
